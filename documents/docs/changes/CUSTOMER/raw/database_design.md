## 1. Purpose

This document describes the database design for the **Customer Management** feature with a **CRUD-only** scope.

The Customer table already exists in the system with the name `tbl_dim_customer`. Therefore, this document **does not propose creating a new Customer table**, but only describes:

- The existing table.
- Existing columns.
- Columns to be added to support soft delete if needed.
- Mapping between business/UI fields and the database.
- Filtering rules based on the parent Organization.
- Reference indexes/constraints for the Phase 1 Spec Pack.

---

## 2. Existing Table

### 2.1 Table `tbl_dim_customer`

Current DDL in the existing source:

```sql
CREATE TABLE IF NOT EXISTS tbl_dim_customer (
    customer_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    organization_id UUID NOT NULL REFERENCES tbl_dim_organization(organization_id),
    customer_alias VARCHAR(255) NOT NULL,
    classification VARCHAR(50) NOT NULL DEFAULT 'INTERNAL',
    status record_status NOT NULL DEFAULT 'ACTIVE',
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    created_by VARCHAR(100) NOT NULL DEFAULT 'SYSTEM',
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_by VARCHAR(100) NOT NULL DEFAULT 'SYSTEM',
    CONSTRAINT uq_customer_alias_per_org UNIQUE (organization_id, customer_alias)
);
```

### 2.2 Existing Columns

| Column | Data Type | Required | Description |
|---|---|---:|---|
| `customer_id` | UUID | Yes | Primary key of the Customer |
| `organization_id` | UUID | Yes | Parent Organization of the Customer |
| `customer_alias` | VARCHAR(255) | Yes | Customer display name/alias |
| `classification` | VARCHAR(50) | Yes | Customer classification, default `INTERNAL` |
| `status` | `record_status` | Yes | Record status, default `ACTIVE` |
| `created_at` | TIMESTAMPTZ | Yes | Record creation timestamp |
| `created_by` | VARCHAR(100) | Yes | User who created the record |
| `updated_at` | TIMESTAMPTZ | Yes | Last update timestamp |
| `updated_by` | VARCHAR(100) | Yes | User who last updated the record |

## 3. Columns to be Added

To support soft delete consistently with Organization Management, the following columns are proposed for `tbl_dim_customer`.

| Column to Add | Data Type | Required | Description |
|---|---|---:|---|
| `deleted_at` | TIMESTAMPTZ | No | Timestamp when the Customer was soft-deleted |
| `deleted_by` | VARCHAR(100) | No | User who performed the Customer soft delete |

The following columns are **not proposed in the current raw requirement**:

- `description`: not available in the current Customer wireframe.
- Multi-language table for Customer name/alias: not within the Customer CRUD scope.
- Dashboard/KPI/score columns: not within the CRUD-only scope.
- `version`: if the Spec Pack decides to apply optimistic locking to Customer similarly to Organization, it must be added in the Phase 1 Spec Pack/Phase 3 design.

## 5. Status Rules

### 5.1 Status Values Used for Customer

| DB Value | Display Label | Meaning |
|---|---|---|
| `ACTIVE` | Active | Customer is being used normally |
| `DELETED` | Deleted | Customer has been soft-deleted and is not displayed in the default list |

### 5.2 Status Handling Rules

- When creating a new Customer, `status` defaults to `ACTIVE`.
- When deleting a Customer, do not physically delete the record.
- When soft-deleting a Customer, update `status = 'DELETED'`.
- Customers with `status = 'DELETED'` are not displayed in the default list.
- Other statuses such as `INACTIVE`, `SUSPENDED`, and `ARCHIVED` are not within the current raw requirement scope unless finalized again in the Spec Pack.

---

## 6. Organization Parent Rules

Customer always belongs to an Organization.

Business/UI-level rules:

- When creating a Customer, only allow selecting Organizations that are active/not soft-deleted.
- When editing a Customer, the Organization dropdown only displays Organizations that are active/not soft-deleted.
- In the Customer List, do not display Customers belonging to Organizations that have been disabled or soft-deleted.

Reference DB/query-level rules:

- The query for the Customer List must join with `tbl_dim_organization`.
- The default Customer List must filter both the Customer status and the parent Organization status.
- Filtering must not only be done on the FE; the BE/query must also exclude Customers belonging to Organizations that are no longer active.

---

## 7. Unique Rules

### 7.1 Existing Unique Constraint

The table currently has the following constraint:

```sql
CONSTRAINT uq_customer_alias_per_org UNIQUE (organization_id, customer_alias)
```

Current meaning:

- Within the same Organization, `customer_alias` must not be duplicated.
- Different Organizations may have the same `customer_alias`.

### 7.2 Points to Finalize in Spec Pack

The following points need to be finalized in the Spec Pack:

- Whether the duplicate check is case-sensitive.
- Whether a Customer that has been soft-deleted can be recreated with the same alias under the same Organization.
- If alias reuse after soft delete is allowed, the current unique constraint must be changed to a partial unique index for non-deleted records.

Example if reuse after soft delete is finalized as allowed:

```sql
CREATE UNIQUE INDEX ux_tbl_dim_customer_org_alias_active
ON tbl_dim_customer (organization_id, LOWER(customer_alias))
WHERE deleted_at IS NULL;
```

---

## 8. Soft Delete Rules

### 8.1 Delete Behavior

When a user deletes a Customer:

- Do not execute `DELETE FROM tbl_dim_customer`.
- Update `status = 'DELETED'`.
- Update `deleted_at = now()`.
- Update `deleted_by = current_user` or the current user ID.
- Update `updated_at = now()` and `updated_by = current_user`.

### 8.2 Restore Deleted Records

The current CRUD scope does not require restoring deleted Customers.

If restore is needed in the future, the following update can be considered:

```sql
status = 'ACTIVE',
deleted_at = NULL,
deleted_by = NULL,
updated_at = now(),
updated_by = :current_user
```

## 9. Proposed Migration SQL

### 9.1 Add Missing Columns

```sql
ALTER TABLE tbl_dim_customer
    ADD COLUMN IF NOT EXISTS deleted_at TIMESTAMPTZ,
    ADD COLUMN IF NOT EXISTS deleted_by VARCHAR(100);
```

### 9.2 Create Indexes for Filtering and Sorting

```sql
CREATE INDEX IF NOT EXISTS idx_tbl_dim_customer_org_status
ON tbl_dim_customer (organization_id, status);

CREATE INDEX IF NOT EXISTS idx_tbl_dim_customer_status
ON tbl_dim_customer (status);

CREATE INDEX IF NOT EXISTS idx_tbl_dim_customer_updated_at
ON tbl_dim_customer (updated_at DESC);
```

### 9.3 Optional Index for Search

If case-insensitive alias search is needed:

```sql
CREATE INDEX IF NOT EXISTS idx_tbl_dim_customer_alias_lower
ON tbl_dim_customer (LOWER(customer_alias));
```

### 9.4 Check Enum/Type `record_status`

The table currently uses the `record_status` type. It is necessary to confirm that this type has `ACTIVE` and `DELETED`.

```sql
SELECT enumlabel
FROM pg_enum
WHERE enumtypid = 'record_status'::regtype
ORDER BY enumsortorder;
```

If `record_status` is a PostgreSQL enum and does not yet have `DELETED`, add the value:

```sql
ALTER TYPE record_status ADD VALUE IF NOT EXISTS 'DELETED';
```

## 10. Sample Queries

### 10.1 Get Default Customer List

Only get active Customers under active/not soft-deleted Organizations:

```sql
SELECT
    c.customer_id,
    c.organization_id,
    o.name_masked AS organization_name,
    c.customer_alias,
    c.classification,
    c.status,
    c.created_at,
    c.created_by,
    c.updated_at,
    c.updated_by
FROM tbl_dim_customer c
JOIN tbl_dim_organization o
  ON o.organization_id = c.organization_id
WHERE c.status = 'ACTIVE'
  AND o.status = 'ACTIVE'
ORDER BY c.updated_at DESC;
```

Notes:

- If Organization only uses `status`, use `o.status = 'ACTIVE'`.
- If Organization has `deleted_at`, the Spec Pack may add the condition `o.deleted_at IS NULL`.

### 10.2 Search Customer by Keyword

```sql
SELECT
    c.customer_id,
    c.organization_id,
    o.name_masked AS organization_name,
    c.customer_alias,
    c.classification,
    c.status,
    c.updated_at
FROM tbl_dim_customer c
JOIN tbl_dim_organization o
  ON o.organization_id = c.organization_id
WHERE c.status = 'ACTIVE'
  AND o.status = 'ACTIVE'
  AND LOWER(c.customer_alias) LIKE LOWER('%' || :keyword || '%')
ORDER BY c.updated_at DESC;
```

### 10.3 Filter by Organization / Classification / Status

```sql
SELECT
    c.customer_id,
    c.organization_id,
    o.name_masked AS organization_name,
    c.customer_alias,
    c.classification,
    c.status,
    c.updated_at
FROM tbl_dim_customer c
JOIN tbl_dim_organization o
  ON o.organization_id = c.organization_id
WHERE o.status = 'ACTIVE'
  AND (:organization_id IS NULL OR c.organization_id = :organization_id)
  AND (:classification IS NULL OR c.classification = :classification)
  AND (:status IS NULL OR c.status = :status)
ORDER BY c.updated_at DESC;
```

### 10.4 Get Active Organization Dropdown

```sql
SELECT
    organization_id,
    name_masked
FROM tbl_dim_organization
WHERE status = 'ACTIVE'
ORDER BY name_masked ASC;
```

If Organization has `deleted_at`:

```sql
SELECT
    organization_id,
    name_masked
FROM tbl_dim_organization
WHERE status = 'ACTIVE'
  AND deleted_at IS NULL
ORDER BY name_masked ASC;
```

### 10.5 Check Duplicate Alias in Same Organization

```sql
SELECT 1
FROM tbl_dim_customer
WHERE organization_id = :organization_id
  AND LOWER(customer_alias) = LOWER(:customer_alias)
  AND customer_id <> :customer_id
LIMIT 1;
```

### 10.6 Create New Customer

```sql
INSERT INTO tbl_dim_customer (
    organization_id,
    customer_alias,
    classification,
    status,
    created_by,
    updated_by
) VALUES (
    :organization_id,
    :customer_alias,
    :classification,
    'ACTIVE',
    :current_user,
    :current_user
)
RETURNING customer_id;
```

### 10.7 Update Customer

```sql
UPDATE tbl_dim_customer
SET
    organization_id = :organization_id,
    customer_alias = :customer_alias,
    classification = :classification,
    updated_at = now(),
    updated_by = :current_user
WHERE customer_id = :customer_id
  AND status <> 'DELETED';
```

### 10.8 Soft Delete Customer

```sql
UPDATE tbl_dim_customer
SET
    status = 'DELETED',
    deleted_at = now(),
    deleted_by = :current_user,
    updated_at = now(),
    updated_by = :current_user
WHERE customer_id = :customer_id
  AND status <> 'DELETED';
```

## 11. Application-layer Validation

| Field | Validation |
|---|---|
| `organization_id` | Required; Organization must exist and be active/not soft-deleted |
| `customer_alias` | Required; maximum 255 characters; duplicate rule to be finalized in the Spec Pack |
| `classification` | Required or default `INTERNAL`; value list to be finalized in the Spec Pack |
| `status` | Only valid values of `record_status` can be used |

Suggested situations:

| Situation | Message Meaning |
|---|---|
| Missing Organization | Organization has not been selected |
| Organization inactive/deleted | Organization has been disabled or soft-deleted and cannot be used to create/edit a Customer |
| Missing Customer alias | Customer alias/name has not been entered |
| Duplicate Customer alias | Customer alias already exists within the same Organization |
| Updating deleted Customer | Customer has been deleted and cannot be updated |
| Deleting already deleted Customer | Customer was already deleted previously |

## 13. Implementation Notes

- Do not create a new `customers` table; use the existing `tbl_dim_customer` table.
- Do not rename `customer_alias` within the current raw requirement scope.
- The business field “Customer Name / Alias” maps to `customer_alias`.
- The Customer List must join with Organization to exclude Customers under inactive/deleted Organizations.
- The Organization dropdown in create/edit must also only retrieve active/not soft-deleted Organizations.
- Customer deletion is a soft delete, not a physical delete.
- Cascade soft delete to Project/Repository and descendant records is within the current Customer CRUD scope.
- The exact child-tree cascade scope should be finalized in the Spec Pack.
