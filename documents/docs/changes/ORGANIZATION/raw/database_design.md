**Ticket ID**: ORGANIZATION   
**Create date**: 2026-06-09  
**Author**: nk_trung  
**Update date**: 2026-06-09  

## 1. Purpose

This document describes the database design for the **Organization Management** function with a **CRUD-only** scope.

Note: The Organization table already exists in the system with the name `tbl_dim_organization`. Therefore, this document **does not propose creating a new table**. It only describes the existing columns, columns to be added, constraints/indexes to be added, and reference migration SQL.

---

## 2. Existing Table

### 2.1 Table `tbl_dim_organization`

Current DDL:

```sql
CREATE TABLE IF NOT EXISTS tbl_dim_organization (
    organization_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name_masked VARCHAR(255) NOT NULL,
    status record_status NOT NULL DEFAULT 'ACTIVE',
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    created_by VARCHAR(100) NOT NULL DEFAULT 'SYSTEM',
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_by VARCHAR(100) NOT NULL DEFAULT 'SYSTEM'
);
```

### 2.2 Existing Columns

| Column | Data Type | Required | Description |
|---|---|---:|---|
| `organization_id` | UUID | Yes | Primary key of the Organization |
| `name_masked` | VARCHAR(255) | Yes | Organization display name in the system. The name must be system-wide unique |
| `status` | `record_status` | Yes | Record status. Used to distinguish active records from soft-deleted records |
| `created_at` | TIMESTAMPTZ | Yes | Record creation time |
| `created_by` | VARCHAR(100) | Yes | User who created the record |
| `updated_at` | TIMESTAMPTZ | Yes | Last update time |
| `updated_by` | VARCHAR(100) | Yes | User who last updated the record |

## 3. Columns to be Added

To satisfy the finalized Organization CRUD requirements, add the following columns to `tbl_dim_organization`.

| Column to Add | Data Type | Required | Description |
|---|---|---:|---|
| `organization_code` | VARCHAR(50) | Yes | Organization code. It can be edited after creation, but the new code must not duplicate another Organization |
| `description` | TEXT | No | Additional description for the Organization |
| `version` | BIGINT NOT NULL DEFAULT 0 | Yes | Version for the Organization |
| `deleted_at` | TIMESTAMPTZ | No | Time when the Organization was soft deleted |
| `deleted_by` | VARCHAR(100) | No | User who soft deleted the Organization |

The following columns are not required:

- `display_code` is not required because it has been decided that **a separate display code different from the internal system code is not needed**.
- A multilingual table for Organization names is not required because it has been decided that **multilingual support for Organization names is not needed**.
- Dashboard/KPI columns such as `risk_score`, `health_score`, and `missing_setup_count` are not required because the current function is **CRUD-only**.

## 5. Status Rules

### 5.1 Status Values Used for Organization

| DB Value | Display Label | Meaning |
|---|---|---|
| `ACTIVE` | Active | Organization is used normally |
| `DELETED` | Deleted | Organization has been soft deleted and is not displayed in the default list |

### 5.2 Status Handling Rules

- When creating a new Organization, `status` defaults to `ACTIVE`.
- When deleting an Organization, the system does not physically delete it and instead updates `status = 'DELETED'`.
- Organizations with `DELETED` status are not displayed in the default list.
- Users can filter the list by: **All / Active / Deleted**.
- Do not use other statuses such as `INACTIVE`, `SUSPENDED`, `ARCHIVED`, `HIGH_RISK`, or `MISSING_SETUP` within the CRUD-only scope.

---

## 6. Unique Rules

### 6.1 Unique Organization Code

`organization_code` must be system-wide unique.

Rules:

- On creation, an existing `organization_code` cannot be entered.
- On update, `organization_code` can be edited.
- The new code after editing must be checked to ensure it does not already exist in another Organization.
- Case-insensitive duplicate checks are recommended to avoid business-level duplicates such as `BRYCEN` and `brycen`.

### 6.2 Unique Organization Name

`name_masked` is used as the Organization name and must be system-wide unique.

Rules:

- On creation, an existing Organization name cannot be entered.
- On update, it cannot be changed to a name that already exists in another Organization.
- Multilingual Organization names are not supported.
- A separate display code is not required.

### 6.3 Unique Check Scope

According to the current business decision, uniqueness is **system-wide**.

This means:

- No distinction is made by tenant/environment within the current table scope.
- One `organization_code` can exist only once in `tbl_dim_organization`.
- One `name_masked` can exist only once in `tbl_dim_organization`.
- Soft-deleted records remain in the DB. If system-wide uniqueness is still applied across the entire table, it is not possible to create a new Organization with the same code/name as a soft-deleted record.

---

## 7. Soft Delete Rules

### 7.1 Delete Behavior

When a user deletes an Organization:

- Do not execute `DELETE FROM tbl_dim_organization`.
- Update `status = 'DELETED'`.
- Update `deleted_at = now()`.
- Update `deleted_by = current_user` or the current logged-in user ID.
- Also update `updated_at = now()` and `updated_by = current_user`.

### 7.2 Restoring Deleted Records

The current CRUD scope does not require restoring deleted Organizations.

If restoration is required in the future, the system can update:

```sql
status = 'ACTIVE',
deleted_at = NULL,
deleted_by = NULL,
updated_at = now(),
updated_by = :current_user
```

## 8. Proposed Migration SQL

### 8.1 Add Missing Columns

```sql
ALTER TABLE tbl_dim_organization
    ADD COLUMN IF NOT EXISTS organization_code VARCHAR(50),
    ADD COLUMN IF NOT EXISTS description TEXT,
    ADD COLUMN IF NOT EXISTS deleted_at TIMESTAMPTZ,
    ADD COLUMN IF NOT EXISTS deleted_by VARCHAR(100);
```

### 8.2 Backfill Organization Code for Existing Data

Because the table already exists, if there is old data in the DB, `organization_code` must be backfilled before converting it to `NOT NULL`.

Example temporary backfill from `name_masked`:

```sql
UPDATE tbl_dim_organization
SET organization_code = UPPER(REGEXP_REPLACE(name_masked, '[^A-Za-z0-9]+', '_', 'g'))
WHERE organization_code IS NULL;
```

Notes:

- The SQL above is only a technical example.
- If duplicate codes may be generated automatically, review and adjust them manually before creating the unique index.
- For production data, export the generated code list and have PM/Admin confirm it before applying constraints.

### 8.3 Make `organization_code` Required

After old data has been backfilled and there are no NULL values:

```sql
ALTER TABLE tbl_dim_organization
    ALTER COLUMN organization_code SET NOT NULL;
```

### 8.4 Create Unique Index for Organization Code

Case-insensitive uniqueness is recommended:

```sql
CREATE UNIQUE INDEX IF NOT EXISTS ux_tbl_dim_organization_code_lower
ON tbl_dim_organization (LOWER(organization_code));
```

### 8.5 Create Unique Index for Organization Name

Because the Organization name currently uses the `name_masked` column, create a unique index on `LOWER(name_masked)`:

```sql
CREATE UNIQUE INDEX IF NOT EXISTS ux_tbl_dim_organization_name_lower
ON tbl_dim_organization (LOWER(name_masked));
```

### 8.6 Create Indexes for Status Filtering and Sorting

```sql
CREATE INDEX IF NOT EXISTS idx_tbl_dim_organization_status
ON tbl_dim_organization (status);

CREATE INDEX IF NOT EXISTS idx_tbl_dim_organization_created_at
ON tbl_dim_organization (created_at DESC);

CREATE INDEX IF NOT EXISTS idx_tbl_dim_organization_updated_at
ON tbl_dim_organization (updated_at DESC);
```

### 8.7 Check Enum/Type `record_status`

The current table uses the `record_status` type. Ensure this type has `ACTIVE` and `DELETED` values.

Example check:

```sql
SELECT enumlabel
FROM pg_enum
WHERE enumtypid = 'record_status'::regtype
ORDER BY enumsortorder;
```

If `record_status` is a PostgreSQL enum and does not yet have `DELETED`, add it:

```sql
ALTER TYPE record_status ADD VALUE IF NOT EXISTS 'DELETED';
```

If `record_status` is not an enum but a domain/custom type, handle it according to the actual definition of the type.

## 9. Sample Queries

### 9.1 Get the Default Organization List

Only active records are retrieved:

```sql
SELECT
    organization_id,
    organization_code,
    name_masked,
    description,
    status,
    created_at,
    created_by,
    updated_at,
    updated_by
FROM tbl_dim_organization
WHERE status = 'ACTIVE'
ORDER BY updated_at DESC;
```

### 9.2 Search Organizations by Keyword

```sql
SELECT
    organization_id,
    organization_code,
    name_masked,
    description,
    status,
    created_at,
    updated_at
FROM tbl_dim_organization
WHERE status = 'ACTIVE'
  AND (
        LOWER(organization_code) LIKE LOWER('%' || :keyword || '%')
        OR LOWER(name_masked) LIKE LOWER('%' || :keyword || '%')
      )
ORDER BY updated_at DESC;
```

### 9.3 Filter by Status

```sql
SELECT
    organization_id,
    organization_code,
    name_masked,
    description,
    status,
    created_at,
    updated_at
FROM tbl_dim_organization
WHERE (:status IS NULL OR status = :status)
ORDER BY updated_at DESC;
```

Parameter convention:

| UI Option | Passed Value |
|---|---|
| All | `NULL` |
| Active | `ACTIVE` |
| Deleted | `DELETED` |

### 9.4 Check Duplicate Code on Creation

```sql
SELECT 1
FROM tbl_dim_organization
WHERE LOWER(organization_code) = LOWER(:organization_code)
LIMIT 1;
```

If the query returns data, the code already exists and creation is not allowed.

### 9.5 Check Duplicate Code on Update

```sql
SELECT 1
FROM tbl_dim_organization
WHERE LOWER(organization_code) = LOWER(:organization_code)
  AND organization_id <> :organization_id
LIMIT 1;
```

If the query returns data, the new code already exists in another Organization and update is not allowed.

### 9.6 Check Duplicate Name on Creation/Update

```sql
SELECT 1
FROM tbl_dim_organization
WHERE LOWER(name_masked) = LOWER(:name_masked)
  AND organization_id <> :organization_id
LIMIT 1;
```

On creation, `organization_id` can be passed as `NULL`, or a separate query without the `organization_id <> :organization_id` condition can be used.

### 9.7 Create New Organization

```sql
INSERT INTO tbl_dim_organization (
    organization_code,
    name_masked,
    description,
    status,
    created_by,
    updated_by
) VALUES (
    :organization_code,
    :name_masked,
    :description,
    'ACTIVE',
    :current_user,
    :current_user
)
RETURNING organization_id;
```

### 9.8 Update Organization

```sql
UPDATE tbl_dim_organization
SET
    organization_code = :organization_code,
    name_masked = :name_masked,
    description = :description,
    updated_at = now(),
    updated_by = :current_user
WHERE organization_id = :organization_id
  AND status <> 'DELETED';
```

### 9.9 Soft Delete Organization

```sql
UPDATE tbl_dim_organization
SET
    status = 'DELETED',
    deleted_at = now(),
    deleted_by = :current_user,
    updated_at = now(),
    updated_by = :current_user
WHERE organization_id = :organization_id
  AND status <> 'DELETED';
```

## 12. Implementation Notes

- Do not create a new `organizations` table; use the existing `tbl_dim_organization` table.
- Do not rename the `name_masked` column in the current change scope to avoid affecting existing data/logic.
- The business field “Organization Name” maps to the `name_masked` column.
- If a clear separation between original name and masked name is needed in the future, create a separate requirement because it may affect existing data.
- Check duplicate data before creating unique indexes for `organization_code` and `name_masked`.
- Deleting an Organization is a soft delete, not a physical delete.
- Do not cascade delete to Customer/Project/Repository/Ticket within the current function scope.
